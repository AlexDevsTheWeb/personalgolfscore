# Milestone v1.0: MVP

**Status:** SHIPPED 2026-06-02
**Phases:** 1–5
**Total Plans:** 12
**Total Tasks:** ~36
**Branching strategy:** none (development branch)

## Overview

This roadmap delivers WHS (World Handicap System) handicap calculation, a shared golf course database, and admin tooling to the existing round-tracking app, plus a unique handicap simulator that lets players project how future scores would affect their index. The work is split into two vertical slices: first the administrative foundation (course database + admin panel), then the player-facing calculation engine (WHS formulas + simulator). Subsequent phases added responsive navigation, Federgolf result import, and an initial HCP-anchored progression chart.

## Phases

### Phase 1: Course Database & Admin Foundation

**Goal**: Establish course database infrastructure with admin management
**Depends on**: Nothing (first phase)
**Requirements**: COURSE-01, ADMIN-01, ADMIN-02, ADMIN-03, ADMIN-04
**Plans**: 3 plans

Plans:

- [x] 01-01: Foundation: types, Firestore service, security rules (Wave 1)
- [x] 01-02: Admin UI Components: AdminRoute, DataGrids, dialogs, snackbar (Wave 2)
- [x] 01-03: Page Integration: admin pages, routes, nav, seed admin (Wave 3)

**Success Criteria:**

1. Admin users can access admin-only pages; non-admin users are redirected away from admin routes
2. Admin can view a list of golf courses, create new courses, edit existing courses, and delete courses via the admin interface
3. Admin can promote other users to the admin role and revoke admin access
4. A public `golf_courses` Firestore collection stores course data (name, PAR, CR, SR per teebox) with proper security rules — public read, authenticated create, admin-only update/delete

### Phase 2: WHS Engine & Handicap Simulator

**Goal**: Enable players to calculate their WHS Handicap Index and simulate future scores
**Depends on**: Phase 1
**Requirements**: CALC-01, CALC-02, SIM-01, SIM-02, SIM-03
**Plans**: 2 plans

Plans:

- [x] 02-01: WHS calculation engine (Score Differential, Handicap Index, Rule 5.2a scaling) and SD storage on round save (Wave 1)
- [x] 02-02: Simulator page with course/teebox selection, Stableford input, current vs projected HI comparison (Wave 2)

**Success Criteria:**

1. User can navigate to the Simulator tab, select a course from the database, and choose a teebox with PAR/CR/SR values
2. User can input hypothetical Stableford scores for 18 holes and the system calculates the correct Score Differential using the WHS formula
3. User can view their current Handicap Index displayed in the simulator
4. User can see a projected Handicap Index alongside their current one, showing what their HI would be with the simulated round included
5. User can verify that simulated data does not appear anywhere in their actual round history (no database writes)

### Phase 3: Navigation & Sidebar Reorg

**Goal**: Make the sidebar the primary navigation hub on all screen sizes; remove HCP/Settings/Logout from Avatar
**Depends on**: Phase 2 (no code dependencies, but follows the new shell composition)
**Requirements**: NAV-01, NAV-02, NAV-03, NAV-04, NAV-05
**Plans**: 2 plans

Plans:

- [x] 03-01: Simplify Avatar to visual-only; add compact SidebarHCP badge (Wave 1)
- [x] 03-02: Sidebar restructure — filter by `show`, remove duplicates, single admin block, SPA navigation via RouterLink, responsive variant switching (Wave 2)

**Success Criteria:**

1. Avatar is visual-only — no dropdown, no popover, no HCP/settings/logout
2. Sidebar drawer is the primary navigation hub on all screen sizes (temporary on mobile, persistent/toggleable on desktop)
3. Sidebar contains compact HCP display, Settings link, and Logout button
4. Admin links render only inside `player.isAdmin` conditional block; no duplicate rendering
5. Navigation links use SPA routing (no full page reload)

### Phase 4: Import Rounds Verification

**Goal**: Let users import Federgolf competition results to verify their handicap against external records
**Depends on**: Phase 2 (uses the WHS engine for SD computation)
**Requirements**: IMPORT-01, IMPORT-02
**Plans**: 2 plans

Plans:

- [x] 04-01: Core logic — CSV/TSV parser, course matcher, round builder, Firestore batch import, store slice (Wave 1)
- [x] 04-02: Import Rounds page UI — paste form, preview table, import result, route, nav link (Wave 2)

**Success Criteria:**

1. User can paste Federgolf competition results (from Google Sheets or similar) into a text area on the Import Rounds page; the app parses CSV/TSV data, matches course names to the `golf_courses` collection, and shows a preview table before import
2. Imported rounds are saved as real Firestore round documents with Score Differential, round totals (Stableford + AGS), and course reference — appearing identically in rounds list, Handicap History, and HI calculations — without per-hole shot data

### Phase 5: Initial HCP, Round HI & Progression Chart

**Goal**: Anchor the handicap model to a user-supplied initial exact HCP value, capture the recalculated WHS Handicap Index and its delta on every saved round, and render a Handicap History chart that starts at the initial HCP and shows it as a dashed reference line
**Depends on**: Phase 2 (WHS engine) and Phase 4 (importRoundsBatch path)
**Requirements**: HCP-INIT-01, HCP-INIT-02, HCP-INIT-03, HCP-INIT-04
**Plans**: 2 plans + 1 gap closure (3 total)

Plans:

- [x] 05-01: Initial HCP input on Settings + per-round HI/delta storage + first-round guard + import path (Wave 1)
- [x] 05-02: Handicap History chart anchored to initialHCP + dashed reference line + Δ column + fallback banners (Wave 2, blocked on 05-01)
- [x] 05-3: Gap closure — CR-01 (imports refresh roundsList), CR-02 (live WHS recalc fallback for legacy users), CR-03 (chart no double-point at first round) (gap_closure)

**Success Criteria:**

1. User can enter an exact initial Handicap value on the Settings page; the value persists to the player document and reappears after refresh
2. After saving a new round, the round document contains `handicapIndex` and `hcpDelta`
3. Imported rounds (Phase 4 path) also receive `handicapIndex` and `hcpDelta`
4. The Handicap History chart starts at initial HCP and progresses through each round's stored `handicapIndex`; dashed reference line
5. The "Current Handicap Index" headline shows the most recent round's stored `handicapIndex`

## Milestone Summary

**Decimal Phases:** None

**Key Accomplishments:**

1. **Admin foundation** — Firebase custom claims identify admins; AdminRoute guard protects admin-only routes at both client (route guard) and server (Firestore rules) layers; full MUI DataGrid-based course and user management with promote/revoke actions
2. **WHS engine** — Pure-function calculation of Score Differential (Rule 5.1) and Handicap Index (Rule 5.2a scaling for < 20 rounds); Handicap Simulator that compares current vs projected HI in ephemeral state with no database writes
3. **Responsive navigation** — Sidebar reorganized as primary hub on all screen sizes; Avatar simplified to visual-only; admin links de-duplicated and gated by `isAdmin`
4. **Federgolf import** — CSV/TSV parser with Italian decimal handling and `Valida=N` filtering; course matcher; per-round writeBatch; preview table before commit
5. **Initial HCP model** — Settings input with strict validation; per-round HI/delta persisted to round document; first-round guard enforced at three layers (Alert, disabled button, throw)
6. **Progression chart** — `@mui/x-charts` LineChart anchored at `initialHCP` with dashed `ChartsReferenceLine`; D-11/D-14/D-15 fallback branches for legacy users and initial-only users; gap-closure plan fixed three integration defects (CR-01, CR-02, CR-03)

**Key Decisions:**

- Branching strategy: `none` — work directly on `development` branch throughout the milestone
- Decimal phase numbering for gap closure: `05-3-PLAN.md` introduced for the three CRs that surfaced during Phase 5 verification
- `@mui/x-charts` v8 dispatcher `ChartsReferenceLine` used instead of plan's `ChartsYReferenceLine` (index-only re-export); behaviorally equivalent for y/label/lineStyle props
- Chart card lifted out of `roundsWithSD.length > 0` guard so the D-14 case (initialHCP + 0 rounds) renders a single point with the reference line
- Per-round writeBatch in `importRoundsBatch` to enable incremental HI computation with running HCP state — each imported round computes its HI from runningSDs + runningHCP sequentially
